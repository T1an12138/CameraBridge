# 2026-09-12 代码检查

## 已修复

- 传输队列没有从 SwiftData 重新加载记录，重启后保留的照片失去导出入口。现在启动时恢复记录和文件 URL，旧进程的未完成任务标为中断，重新选择后可重试。
- 相同对象反复选择会生成多个任务。现在使用不透明媒体 ID 去重，并覆盖同一批次、运行中和重启后已完成记录。
- 清除已完成任务会隐藏尚未导出的原图。现在仅允许清除同时已成功导入相册和导出 Files 的完成项。
- 迟到的取消操作或进度轮询可能回退完成状态。现在忽略终态取消，并在发布最终状态前等待轮询退出。
- 重试复用同一个暂存路径可能与旧 partial 冲突。现在每个 iOS 传输使用独立 UUID 文件名，Photos 中仍保存相机原始文件名。
- Rust 下载完成时的普通重命名在目标文件竞争下可能覆盖原图。现在默认用不可覆盖的原子硬链接发布；显式替换不再先删除旧文件。无硬链接支持的文件系统会报错并保留 partial。
- Swift 的两个空返回值 continuation 补上明确类型；CI 补上 `apps`、`.cargo` 变化触发，以及固定 Cargo 输出目录；Xcode 测试目标补齐 Info.plist 生成设置和中文开发语言。
