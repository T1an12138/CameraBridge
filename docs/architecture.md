# CameraBridge 架构

## 职责边界

Rust 核心负责 PTP/PTP-IP 帧处理、命令与事件通道、事务串行化、Nikon 行为、流式下载、取消和完整性检查。Windows CLI 与 iOS 绑定层使用的是同一套实现。

Swift 负责 Apple 平台特有的行为：加入已知 Wi-Fi 网络、本地网络隐私诊断、Keychain、SwiftData、PhotoKit、文件导出、UI 状态和应用生命周期。

大型媒体载荷绝不跨越 FFI 边界。Rust 使用经过净化的相对文件名写入调用方提供的暂存根目录，校验声明长度，并在完成后以原子方式将 `.partial` 文件提升为完整文件。

## Rust 包

- `ptp-codec`：严格的小端序 PTP 数据集和操作容器。
- `ptpip`：PTP/IP 数据包编解码器、命令/事件通道、事务状态和传输超时。
- `camera-core`：品牌无关的公共模型、驱动 `trait`、传输快照和错误分类。
- `nikon-driver`：Z6 II C 1.70 能力配置和 Nikon 专属映射。
- `camera-ffi`：不暴露原始 Nikon 句柄的窄 UniFFI 外观层。
- `camera-cli`：Windows 硬件探测和脱敏诊断。
- `mock-camera`：用于集成测试和故障测试的确定性 PTP/IP 对端。

## 发现策略

已实现的 Windows 探测工具会验证显式提供的单播端点，且绝不扫描子网。实体相机的发现机制仍有待观测；执行真机测试时，请记录 Z6 II 实际支持以下哪种机制：

1. 稳定的单播端点；
2. 确切的 Bonjour 服务；
3. 仅组播发现。

项目未实现子网扫描。由于 Apple 要求受管理的组播权限，仅组播发现是 iOS 发布门槛。

## 会话与传输策略

- v1 只允许一个相机会话和一条串行化的 PTP 事务流。
- 下载串行执行。可以重复取消同一传输，而不会改变结果。
- 除非实体相机声明相关能力并通过显式能力测试，否则禁用部分对象续传。
- 如果局部读取不可用，重连时会保留队列中已完成的项目，并仅重新开始当前文件。
- 协议错误和网络错误使用类型表示；字符串展示由 Rust 核心之外的层负责。

## FFI 策略

UniFFI 0.31.2 固定在手写 Swift `actor` 之后。SwiftUI 绝不直接调用生成的 API。Swift 传输队列每秒最多轮询 Rust 快照四次；媒体字节绝不跨越 FFI。取消 Swift 任务时，会调用幂等的 Rust 传输取消方法。

如果 macOS PoC 未能通过 Swift 6 严格并发编译、取消传播或 1,000 次循环生命周期测试，则只将 `camera-ffi` 替换为窄 C ABI。其他 Rust 包保持不变。
