# CameraBridge Nikon Z6 II 导入器设计

## 目标

提供一款本地优先的 iOS 导入器：它能够可靠连接处于直连 Wi-Fi 接入点模式的 Nikon Z6 II C 1.70、浏览 JPEG/NEF 媒体、在前台下载选中的原始文件、将其添加到 Photos，并保留导出到 Files 的路径。

当前 Windows 里程碑使用后续 iOS 应用将采用的完全相同的 Rust 核心来验证协议。配备 Xcode 26+ 的 Mac 和 Apple Developer Program 会员资格，是 iOS 构建验证与 TestFlight 的明确门槛。

## 产品边界

用户手动启用相机热点。CameraBridge 将已知 SSID 和密码存储在 Keychain 中，临时加入该网络，请求本地网络访问权限，建立 PTP/IP，然后显示分页的相机媒体网格和串行传输队列。每个连接阶段都清晰可见且可重试。

V1 仅支持 JPEG 和 NEF。它不包含 BLE 配对/自动传输、后台联网、视频、遥控拍摄、USB、其他相机型号、云端账号和遥测。

下载数据以流式方式写入应用自有暂存根目录下的 `.partial` 文件。Rust 核心会校验相机声明的大小，并以原子方式提升该文件。Swift 通过 PhotoKit 仅添加（`add-only`）访问权限执行导入。成功导入的文件会保留 24 小时，以便导出到 Files；失败或尚未导出的文件会一直保留，直至问题解决。

## 架构

Rust 负责 PTP/PTP-IP 编解码器、命令与事件套接字、事务串行化、Nikon 映射、超时/重连策略、逐文件取消和完整性检查。Windows CLI、模拟相机和 iOS 绑定层均使用同一核心。

Swift 负责 `NEHotspotConfigurationManager`、本地网络诊断、Keychain、SwiftData、PhotoKit、Files 导出、UI 状态和前台生命周期。SwiftUI 界面外壳提供“相机”和“传输”两个标签页，以及由 `enum` 驱动的“设置”弹出页。应用服务通过环境注入，各功能的局部状态仍保留在本地。

UniFFI 0.31.2 有意只暴露窄任务/DTO 外观层。Rust 将媒体直接写入暂存目录；只有缩略图和节流后的进度会跨越 FFI。手写 Swift `actor` 会隔离生成的绑定代码，并将 Swift 取消映射到幂等的 Rust `TransferJob.cancel()`。

## 可靠性约定

连接错误使用类型表示，并映射到一个可执行的恢复操作：热点/密码错误、本地网络权限被拒、相机不可达或休眠、相机忙、固件不受支持、协议违规、会话丢失、存储空间不足、完整性失败或取消。

v1 中的命令和下载均串行执行。队列中已完成的项目在重连后仍会保留。只有通过 Z6 II 能力测试后才会启用按字节偏移续传；否则会安全地重新开始当前文件，同时保持已完成文件的完成状态。

诊断信息包含版本、状态转换、耗时、操作名称、响应码、重试次数、字节数和哈希。它不包含密码、媒体字节、缩略图、不必要的文件名和 EXIF。

## 验收

Windows 硬件门槛包括：执行 20 轮连接/列目录/断开循环，至少 19 轮首次尝试成功且能在一次重试内恢复；媒体列表就绪时间的 p95 不超过 15 秒；对 500 个对象稳定分页；跨越三次强制断线下载 50 个混合的 JPEG/NEF，且不出现误标完成或重复标识。重复下载与通过 USB/存储卡单独复制的文件必须具有相同的 SHA-256。

macOS/iOS 门槛要求：通过 Swift 6 严格并发编译；1,000 次 FFI 对象生命周期循环无泄漏或崩溃；十次冷连接全部成功；二十组 JPEG+NEF 通过中断场景测试；权限/存储恢复正确；并在 TestFlight 前完成实体 iPhone 验证。
